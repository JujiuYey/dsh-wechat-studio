# Agent-Ready CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose `dsh-wechat-studio`'s core capabilities (layout, Zhuque detection, SVG cards, cover generation, personal writing style, articles, and insights) as a zero-dependency Node.js CLI (`wechat-studio`) for external Agents and scripts while preserving 100% compatibility with the existing DeepSeek Harness (DSH) plugin.

**Architecture:** Keep `src/host.js`, `src/ai.js`, `src/pipeline.js`, and `client/*` completely intact so DSH plugin behavior cannot regress. Add a standalone OpenAI-compatible `ctx` adapter (`src/cli-llm.js`) that implements the exact `{ llm.prepareCall, agentDefaultModel.currentSelection }` interface `src/ai.js` already consumes, plus a testable CLI runner (`src/cli.js`) and executable entrypoint (`bin/wechat-studio.js`). Support `--json` structured output across all subcommands, shared `--data-dir` storage with the DSH plugin, and `--prompt-only` mode on LLM commands so external Agents can optionally use their own models without configuring a second model key.

**Tech Stack:** Node.js `>=20` ESM, built-in `node:util` (`parseArgs`), `node:test` + `node:assert/strict`, zero new runtime dependencies, existing `src/*.js` domain modules.

**Spec:** User-confirmed requirement: expose all core studio capabilities via CLI for external Agents, strictly preserving existing DSH plugin functionality.

## Global Constraints

- **Zero DSH Plugin Regression:** Do NOT alter `package.json` `main`, `exports`, `dsh`, or `engines` fields; do NOT modify `src/host.js`, `src/ai.js`, `src/pipeline.js`, or `client/*` unless an explicit, backward-compatible pure helper export is needed. Every existing test in `test/*.test.js` and `npm run build` must remain 100% green.
- **Zero New Dependencies:** Use Node.js `>=20` built-ins (`node:util` `parseArgs`, `fetch`, `AbortController`, `node:fs/promises`) only.
- **Strict `--json` Contract:** When `--json` is passed, `stdout` MUST contain ONLY one valid JSON object (`{ ok: true, ... }` or `{ ok: false, error, code }`); diagnostics/warnings go strictly to `stderr`.
- **Deterministic Exit Codes:** `0` = success, `1` = runtime/API/domain error, `2` = invalid CLI arguments or missing required flags/files.
- **Workspace Isolation:** Default `--data-dir` resolves to `join(dshHome(), 'wechat-studio')` (sharing drafts, settings, skills, and insights with the DSH plugin); `--data-dir <path>` overrides it cleanly so Agents and tests never pollute the user's live workspace.
- **Shell PATH:** All verification commands prefix `export PATH="/opt/homebrew/opt/nodejs/bin:/opt/homebrew/bin:/usr/local/bin:$PATH"`.
- **Commit Policy:** Never run `git commit` without explicit user approval in interactive sessions.

## Review Focus

1. **DSH Plugin Zero-Regression & Packaging:** Adding `bin/wechat-studio.js` and `"bin"` to `package.json` must also include `"bin"` in `"files"` (for `npm pack`) without breaking `exports`, `dsh` plugin metadata, `npm run build`, or any existing test -> pinned in Task 2 & Task 6.
2. **Strict `--json` stdout purity & exit codes:** Missing files, unknown flags, or runtime errors must never leak plain text or stack traces into `stdout` when `--json` is set, and must return exit code `2` (usage) or `1` (runtime) -> pinned in Task 2 (`runCli` framework tests).
3. **Zero key leakage:** Provider keys must never appear in `stdout`, `stderr`, error messages, or `--json` outputs -> pinned in Task 1 & Task 4.
4. **Standalone OpenAI-compatible LLM edge cases:** `createStandaloneCtx` must handle SSE streaming (including multi-chunk splits and `[DONE]`), non-streaming JSON fallback, HTTP 401/429/500 errors (scrubbing keys), and `AbortSignal` cancellation -> pinned in Task 1.
5. **Shared atomic storage & `--prompt-only` contract:** `articles import`, `insights import`, and `style apply`/`restore` must go through the exact same `Store` / `JsonStore` / `applyWritingStyle` atomic helpers as DSH; `--prompt-only` must work with **zero** model key configured -> pinned in Tasks 3, 4, 5.
